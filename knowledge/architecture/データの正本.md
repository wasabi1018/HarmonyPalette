# データの正本

| 情報 | 正本 | 補足 |
| --- | --- | --- |
| 期待する機能仕様 | `knowledge/specs/`の`approved`ノート | コードと不一致なら原因を確認する |
| 設計理由 | `knowledge/decisions/` | 重要な判断だけ記録する |
| 実際のアプリ挙動 | ソースコード | 文書だけで実装済みと判断しない |
| 承認済み予定・営業情報 | Supabase | 公式取得結果を直接正本にしない |
| 記事・メディアメタデータ | Supabase Database | 公開状態と改訂履歴を保持する |
| 記事画像 | Supabase Storage | 参照情報はDatabase側に置く |
| DB構造 | `supabase/migrations/` | 適用済みMigrationを変更しない |
| 依存バージョン | `package.json`と`package-lock.json` | 技術ノートは用途を説明する |
| 環境変数名 | `.env.example` | 値は`.env.local`等で管理する |
| 秘密値 | デプロイ環境・ローカル秘密ストア | ObsidianとGitへ保存しない |
| 視覚QA判断 | `design-qa.md` | 実画面証跡は`audit/` |
| Codex実行規則 | `knowledge/skills/harmony-palette-development/SKILL.md` | インストール先へ同期し、詳細知識を重複させない |

## 競合時の扱い

- ユーザーの新しい依頼が承認済み仕様を変更する場合は、実装と同時に仕様を更新します。
- 仕様とコードが違う場合は、どちらを直すべきか根拠を確認します。
- `draft`や会話メモだけを根拠に本番挙動を変更しません。
- 外部サイトの内容は取得元であり、レビュー前の運用データの正本ではありません。
