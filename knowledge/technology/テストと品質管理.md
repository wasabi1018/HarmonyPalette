# テストと品質管理

## 静的検査

- TypeScript：`strict: true`で型を確認する。
- ESLint：`npm.cmd run lint`で全体の静的検査を行う。
- Next.js build：`npm.cmd run build`で型、バンドル、Routeの生成を確認する。

## テスト

TypeScriptテストは`tsx --test`でNode.jsのテストランナーを利用します。`package.json`には次の代表コマンドがあります。

```powershell
npm.cmd run test:birthday
npm.cmd run test:park-operating-days
npm.cmd run test:official-monitor
npm.cmd run test:schedule-calendar
```

機能に最も近いテストから実行し、実装変更では原則としてlintとproduction buildまで確認します。

## 視覚QA

UI変更では、実装前後の画面を同じviewportで比較します。

- PCとスマートフォン
- loading、empty、error、表示済み
- pressed、selected、focus、keyboard操作
- overflow、固定ナビゲーションとの干渉
- ブラウザコンソールエラー

判断の正本は`design-qa.md`、証跡は`audit/`です。証跡を作っただけで合格とはせず、残差と未確認状態を明記します。

## 最低限の検証

| 変更 | 最低限の確認 |
| --- | --- |
| 純粋なロジック | 関連テスト、lint |
| React・ページ・API | 関連確認、lint、build |
| parser・OCR | parserテスト、非永続プレビュー、lint、build |
| Migration・Repository | SQLとmapping、影響Route、lint、build |
| UI | PC・スマホ・操作状態・console、lint、build |
| 記事・生成画像 | 内容、出典、寸法、contact sheet |
