# データベースと認証

## Supabaseの役割

Supabaseは、承認済みスケジュール、営業情報、記事、メディアメタデータ、各種設定、分析データの正本です。

| 機能 | 使用するSupabase機能 |
| --- | --- |
| 運用データ | PostgreSQL Database |
| 管理者ログイン | Supabase Auth |
| 記事画像 | Supabase Storage |
| 権限 | RLS、管理者判定、サーバー専用Secret Key |
| DB変更履歴 | `supabase/migrations/` |

## クライアントの種類

- `lib/supabase/client.ts`：ブラウザ用。公開可能なURLとPublishable Keyだけを使用する。
- `lib/supabase/server.ts`：サーバー用の読み取り・管理クライアントとインポート認可。
- `lib/supabase/auth-middleware.ts`：管理画面・管理APIのAuthセッション更新。
- `lib/supabase/auth-server.ts`：管理者ロールまたは許可メールの判定。
- `lib/supabase/*-repository.ts`：DB行とアプリケーションの型の境界。

## 認証経路

`middleware.ts`は`/admin/:path*`と`/api/admin/:path*`を対象にSupabase Authセッションを更新します。権限付き変更は、ログイン状態だけでなく管理者判定を通過させます。

## 環境変数

名前と用途は`.env.example`、構築手順は`SUPABASE_SETUP.md`が正本です。主な分類は次のとおりです。

- 公開可能：`NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
- サーバー限定：`SUPABASE_SECRET_KEY`
- 管理者・運用：`ADMIN_EMAILS`、`ADMIN_IMPORT_SECRET`、`CRON_SECRET`

値はObsidian、ログ、Gitへ記録しません。

## DB変更

スキーマ変更では新しいタイムスタンプ付きMigrationを追加します。適用済みのMigrationを書き換えません。既存データ、NULL移行期間、RLS、Storage Policy、インデックス、復旧方法、Cronへの影響を確認します。リモート適用はユーザーの明示的な依頼がある場合に限ります。

分析データのうち日次UUは、`site_daily_unique_visitors`で日本時間の日付と匿名ハッシュの重複を排除し、`site_daily_events`へ日別合計を保存します。重複排除用の行は当日と前日に限定し、生のブラウザ識別子はDBへ保存しません。

サイト分析は7・30・90日間の集計に加え、各項目の計測開始から日本時間の今日までに保存された日別データの累計を表示します。累計は選択期間に依存せず、UUは日次UUを足した延べ数です。人気記事は選択期間の閲覧数順を維持し、記事ごとの累計閲覧数も併記します。CSVには期間合計と累計を含めます。既存の`article_daily_views`と`site_daily_events`をページ分割して読み取るため、追加のMigrationは不要です。

混雑予想ページの訪問は`crowd_forecast_view`として保存し、期間合計・今日・1日平均・累計・日別グラフ・CSVへ反映します。TOP訪問と同じく、各ページにつき同じタブ内の日本時間の同じ日に1回として数えます。集計対象の追加には`20261019005948_site_analytics_crowd_forecast.sql`の適用が必要です。過去の未計測アクセスは補完しません。既存のTOP訪問・日次UUなどの集計を保持します。
