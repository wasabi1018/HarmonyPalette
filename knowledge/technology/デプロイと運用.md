# デプロイと運用

## Node.js

Node.js は本番の Vercel と同じ 24 系列を使用し、最低バージョンを **24.22.1** とします。2026年10月21日の[公式セキュリティリリース](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases)を反映したバージョンです。

`package.json` の `engines.node` と `package-lock.json` に必要な範囲を定義し、`.nvmrc` と `.node-version` にローカル開発・CI用のバージョンを指定しています。Node.js を切り替えてから依存関係のインストール、テスト、buildを実行します。

Vercel は `engines.node` に従って 24 系列を選択し、パッチはプラットフォーム側で配布されます。`npm.cmd run build` は最初に `node --version` を出力するため、修正版の適用は、新しいデプロイのビルドログに出力される実際の Node.js バージョンで確認します。

## Vercel

Next.jsアプリケーションの配信先として使用します。`vercel.json`には予約記事公開用のCronが定義され、`/api/cron/publish-articles`をUTCスケジュールで呼び出します。

Cron Routeは`CRON_SECRET`などのサーバー限定設定で保護します。時刻を説明するときは、Vercel設定のUTCと運用上の日本時間を混同しません。

## Next.jsの実行コマンド

```powershell
npm.cmd run dev
npm.cmd run build
npm.cmd start
npm.cmd run lint
```

コマンドの正本は`package.json`です。

## 環境

- 変数名と例：`.env.example`
- ローカル秘密値：`.env.local`
- Supabase構築：`SUPABASE_SETUP.md`
- Next.js設定：`next.config.mjs`
- Cron設定：`vercel.json`

## 外部変更の境界

以下は、ユーザーの明示的な依頼がある場合だけ実行します。

- 本番デプロイまたは昇格
- リモートMigration適用
- Seed実行
- 公式インポートの永続化
- 記事・予定の公開
- Supabase Storageへのアップロード
- Cronまたは管理APIの本番呼び出し

## リリース確認

変更内容に応じて、build、対象テスト、公開画面、管理画面、認証、環境変数、metadata、canonical、sitemap、robots、feed、Cronを確認します。資格情報や外部接続がなく確認できない項目は、ローカル確認と明確に区別して報告します。
