# 記事の楽天PR

記事の読み進めやすさを保ち、上部バナー、本文途中の商品2件、本文末尾の共通商品4件を掲載できるようにする。

| 位置 | 設定単位 | 表示 |
| --- | --- | --- |
| タイトル・アイキャッチ下、目次の前 | 通常は共通の `article-top`、記事ごとの `article-banner-{記事UUID}` で上書き可能 | 元の縦横比で中央寄せ、スマホは縮小 |
| 選んだ本文見出しの手前 | 記事ごとの `article-inline-{記事UUID}` | PC・スマホとも1行2件 |
| 本文末尾、著者紹介・シェアの前 | TOPの `home-pickup` を共有 | PC・スマホとも2列×2行4件 |

## 管理

記事編集の「楽天PR」から、この記事の商品・挿入位置、この記事の上部バナー、全記事共通の上部バナー、TOP・記事末尾の共通商品を別タブで開ける。新規記事は下書きを保存してIDを作ってから設定する。本文の未保存変更は広告設定画面に反映しない。

「楽天PR管理」→「記事ごとの設定」でも対象記事を選べる。楽天API検索、2商品の選択、並び替え、短い紹介文、見出し・説明、挿入先の見出し、公開オン／オフ、プレビューを管理する。公開するには2件の有効な商品と挿入先が必要。広告設定の保存は公開済み記事に反映する。非公開記事は引き続き公開ルートから取得できない。

見出しは保存済み本文から生成したIDで参照する。トップレベルの見出しだけを候補にし、リストや引用を分断しない。本文編集で挿入先が消えた場合は本文途中の商品だけを非表示にする。管理画面では選び直して修復でき、商品選択は保持する。

上部バナーは「共通バナー」の掲載場所「全記事共通の上部バナー」でコードを取り込んで保存する。未設定時はユーザー指定の楽天バナーを初期値として公開オンにする。初期画像・リンクはTOPと共通だが、保存済みの設定はTOPと独立し、明示的な公開オフも維持する。「記事ごとの設定」→「この記事の上部バナー」で通常は共通設定を使用し、必要な記事だけ個別バナーへ変更できる。個別設定を公開オフにすると、その記事だけ上部バナーを隠す。共通設定に戻せば最新の共通バナーを使用する。本文末尾は「共通の商品紹介」でTOPと同じ4件・紹介文・表示設定を管理する。

## 保存・公開境界

既存の非公開 `site-settings` Storage内の `rakuten-pr/` と `rakuten-banners/` を再利用する。商品データ・認証・URL検証は既存機能と共通。DBスキーマ変更や環境変数追加は不要。管理者認証の後に記事の存在を確認し、保存時に最新本文の挿入先を検証する。公開表示は公開済みの記事を入力にし、管理用の記事取得を呼ばない。取得障害、破損、表示オフは本文・関連記事の表示を妨げない。

記事の改訂・複製と広告設定は別保存。複製した記事は新しいUUIDとなるため、本文途中の商品・個別バナーは自動コピーしない。元記事の設定は保持する。複製先は上部バナーを共通設定から継承し、末尾の共通商品も共有する。個別バナーは `mode: inherit | custom` を非公開Storageに保存する。存在しない記事の設定は作成できず、壊れた個別設定を共通バナーで迂回しない。

記事本文・目次・読み上げ・読み時間・SEO構造化データを商品データで書き換えない。すべての広告にPR表記、スポンサーリンク属性、別タブ遷移を付け、印刷時は広告を隠す。本文の分割には既存の依存ツリーにある `htmlparser2` を直接依存として明示する。

実装入口：`lib/rakuten-article.ts`、`lib/rakuten-article-data.ts`、`lib/rakuten-article-banner-data.ts`、`lib/articles/rakuten-content.ts`、`components/article-rakuten-body.tsx`、記事詳細・楽天PR管理・記事編集。

検証：`npm run test:rakuten`、lint、production build、記事をまたぐ設定の独立性、見出し変更・修復、管理操作、PC・スマホの配置。証跡：`audit/article-rakuten-2026-10-07/`。
