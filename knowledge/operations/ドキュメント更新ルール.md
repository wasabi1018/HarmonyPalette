# ドキュメント更新ルール

## 変更と更新先

| 変更 | 更新先 |
| --- | --- |
| ユーザー向け挙動 | `knowledge/specs/` |
| データの責任分界 | `knowledge/architecture/データの正本.md` |
| 重要な設計選択 | `knowledge/decisions/` |
| 新技術・主要ライブラリ | `knowledge/technology/` |
| 本番運用・検証手順 | `knowledge/operations/` |
| 視覚基準・証跡 | `design-qa.md`、`audit/` |
| DB構造 | 新しい`supabase/migrations/` |
| 依存バージョン | `package.json`、`package-lock.json` |

## 完了条件

文書変更を伴う実装は、次を満たして完了とします。

- 状態と更新日が正しい。
- 実際のコードパスを記載している。
- 正本を重複させていない。
- 秘密値を含まない。
- 廃止したリンクや用語が残っていない。
- 実施した検証と未確認事項を完了報告に含める。

## レビュー観点

- 「必ず」「してはならない」「推奨」を意図どおり使い分けているか。
- 技術の一般論ではなく、このプロジェクトでの用途が書かれているか。
- 主語、実行者、対象環境、公開範囲が明確か。
- 相談内容を自動的に確定仕様へ変えていないか。
