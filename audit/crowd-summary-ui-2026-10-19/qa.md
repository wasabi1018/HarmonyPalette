# 1日スケジュールの混雑・天気UI整理

2026-10-19。対象は `DailyForecastSummary` を共用する `/daily-schedule` とTOPの今日のスケジュール。

## 画面目標

ユーザー添付 `.codex-remote-attachments/01a1547b-26da-7830-a4b3-f988eb467d29/00541e1a-e748-4dc3-9065-386d51e68fe1/1-8199.jpg` の、混雑度・天気・補足・カレンダーボタンが折り返して混在する状態を整理する。

- 上段は混雑度とカレンダーへの導線。色とラベル、基本予想の注記を維持。
- 下段は天気・最高最低気温と、営業時間に重なる時間帯別降水確率。
- 地域と過去日の予報の区別は常時表示。地点・気象庁への出典リンク・発表日時はネイティブのdetails/summaryで開く。
- 読み込み中と準備中には意味のない空の色見本を省く。日付変更で詳細を閉じる。

## 検証

既存の `scripts/preview-crowd-forecast.ts` とローカル専用サンプルを使用。インメモリDBから既存の公開APIを経て描画し、本番データや外部の天気取得は操作していない。サンプルの天気・予定は表示検証用であり、実際の予報・予定の証拠ではない。

混雑表示APIは確認した各日でHTTP 200。ページ閲覧の分析APIはこのfixtureの対象外のため503となる。分析の永続化は本検証の範囲外。

| 確認 | 結果 |
| --- | --- |
| 320・390・1440px | 横幅超過なし。390px設定時はscrollWidth/clientWidthとも375px、320px設定時はとも305px、1440px設定時はとも1425px（デスクトップのスクロールバーを除く） |
| 詳細 | クリックとEnterで開閉、気温の地点・出典・発表日時を確認。日付変更後に閉じることを確認 |
| 日付とAPI | 翌日ボタンで日付・URL・混雑表示が切り替わる。読み込み中の文言を確認 |
| 表示状態 | 普通・休園日・予想準備中・基本予想・天気未取得を確認。長い天気文でもはみ出さない |
| 欠損 | 最高最低気温が「—℃」、日単位降水確率が「—%」。欠損を0に置き換えない |
| カレンダーリンク | 44px高を維持し、クリックで `/crowd-forecast` のカレンダーが表示される |
| TOP | 今日のスケジュールで同じ整理が反映される |
| Console | 確認対象タブのerror/warnなし |
| 全体lint | `npm.cmd run lint` 成功 |
| 本番ビルド | `npm.cmd run build` 成功、型検査を含む |

最初の320px確認で準備中のラベルが折り返したため、色見本を省いて状態文言を12pxにし、1行になることを再確認。長い天気文・基本予想は必要に応じて自然に改行する。
