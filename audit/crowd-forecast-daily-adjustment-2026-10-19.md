# 混雑予想：当日の日別調整が反映されない不具合

- 対象：2026-10-19の「運動会振替休日」＋5点。
- 本番読み取り時：revision 20。設定には調整が保存済みだが、10/19の公開スナップショットは30点・manual 0・topics空のまま。最終計算は10/18。
- 原因：設定プレビュー・保存と定期更新が同じ `mergeForUpdate` を使い、どちらも `input.date <= today` を更新対象から除外していた。
- 修正：設定保存前または保存後の設定に当日の日別調整がある場合のみ、保存済み天気で当日も再計算する。既存の未反映の調整の再保存、調整の追加・変更・削除に対応。定期更新、日別調整のない通常保存、過去日の固定は維持。
- 本番保存データをコピーした非永続プレビュー：30→35点、manual 0→5、topicsに「運動会振替休日」を追加。混雑区分はnormal（普通）のまま。保存済み天気は一致。
- 検証：`npm.cmd run test:crowd-forecast` 33件成功、全体lint成功、production build成功。ビルドは専用distDir `.tmp/crowd-forecast-fix-build` を使用。ビルドが追加したtsconfig・next-envの参照変更は除去。
- 変更前の本番調査：読み取りのみで原因と非永続プレビューを確認した。
- 本番反映手順：修正を公開し、保存済みの設定をプレビュー・再保存して10/19を再計算する。再保存時に当日の加点5・理由・天気と過去日の保持を確認する。公開APIには点数・非公開メモを含めない。
