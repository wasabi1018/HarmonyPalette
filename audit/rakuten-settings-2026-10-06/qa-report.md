# 楽天API設定 — 2026-10-06

## 対象

管理メニュー → 楽天API設定 → 入力 → 管理者API → 楽天の商品検索による接続確認 → 非公開Storageへ保存 → 再読み込み後に登録状態を表示する。

公開サイトへの商品紹介カード配置と本番反映は今回の対象外。

## 実施した検証

| 境界 | 結果と証拠 |
| --- | --- |
| 管理画面の認証 | 未ログインで設定ページを開くと既存のログイン画面へ移動。架空の管理者でログイン後、管理メニューから実際の設定ページを表示。 |
| APIの認証 | 実際のローカルAPIへ認証なしのGETは401。全メソッドの未ログイン・権限なし・認証未設定の拒否は統合テストで確認。 |
| 入力と接続確認 | 実際のフォームからPOST。ローカルの楽天応答を受け、商品名とアフィリエイトリンク取得成功を表示。直後の保存先状態は `uploads: 0, stored: false`。 |
| 設定保存 | 同じフォームからPUT。Supabase SDKの実際のStorage呼び出しをローカルサービスで受け、非公開バケット作成と保存を確認。保存件数は1。 |
| 再読み込み | 実際のページを再読み込みして「保存済み」「登録済み」と保存日時を表示。3つの入力はすべて空欄・password型。 |
| 保存済みの接続確認 | 入力欄を空欄のまま再接続し成功。保存件数は1のまま。 |
| 接続エラー | ローカル楽天サービスの403を、フォームに一般化した日本語エラーとして表示。保存は行われない。 |
| PC・スマートフォン | CSS viewport 1280×900、375×844で表示。横のはみ出しなし。両操作ボタンの高さ44px。 |
| ブラウザーコンソール | 通常の入力・接続・保存・再読み込み時、error/warnログは空。 |

`01-desktop-saved.png` は保存・再読み込み後のPC画面。`02-mobile-connected.png` は保存済みの認証情報で接続確認に成功したスマートフォン画面。`mobile-metrics.json` にDOM計測を保存した。画像には架空のアカウントとローカルURLのみを使用している。

## 検証方法と制限

- `qa-server.mjs` はループバック上の架空のSupabase Auth/Storageと楽天応答を提供する検証用起動スクリプト。アプリ本体の認証、管理ページ、API、Repository、SDKは通常のコードを使用した。
- 楽天接続の差し替えは、このローカル起動スクリプトからのみ読み込む `rakuten-api-fixture.cjs` に限定。アプリ本体に接続先変更用の設定や認証バイパスを追加していない。
- 未保存の入力がある際の別画面への移動確認は、ブラウザー検証ツールが標準確認ダイアログの操作で停止したため、承認・キャンセル後の遷移を完了まで自動検証できなかった。通常の入力・接続・保存の検証後に発生したツール上の制限であり、この移動確認を成功済みとは扱わない。
- 検証サーバーは停止済み。一時的なブラウザータブの終了と表示サイズの復帰も試みたが、ダイアログで検証ツールが停止したため、終了の確認はできていない。
- 実際の楽天キー、本番Storage、楽天側のアプリ権限、実際のネットワーク接続は未確認。本番データの保存・デプロイは行っていない。
