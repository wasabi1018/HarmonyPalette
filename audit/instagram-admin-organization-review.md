# Instagram管理画面の整理・検証記録

日付：2026-10-04

## 実装

- Instagramトップに作成ツール5種類、DM運用、サイト表示設定の入口を配置。
- 作成ツール、DM一覧／作成／詳細／送信状況、設定を個別ページへ分離。
- 共通メニュー、パンくず、作成ツールへ戻る導線を追加。
- 対象条件・混雑予想の編集・投稿URL・DM入力とPNGを、管理レイアウトに属するメモリ上の状態で保持。
- 推しキャラ画像から対象月の下書きへ直接登録するパネルを追加。
- 予定画像の補助設定を開閉式に整理。画像生成・集計・DMの開始／停止は既存の処理を使用。
- DMのID指定取得に対応し、一覧の最近30件から外れたキャンペーンも詳細ページで取得。
- 管理レイアウトを動的処理に指定し、認証設定のないビルドでもログイン転送を事前生成しないよう修正。認証条件は既存の処理を使用する。

## 確認済み

- 関連テスト13件：成功。休園日・表示順・日別画像の週範囲、機能別の編集保持、PNGファイルの引継ぎ、状態の隔離、DMキーワード・Webhook解釈・Origin制約を確認。
- 専用コピーのlint／本番ビルド（型チェックを含む）：成功。検証スクリプトのlintもエラー・警告なし。
- ワークスペースの型チェック：今回の変更対象にエラーなし。既存の未コミット原稿スクリプトに型エラーがあるため、全体は失敗。
- `git diff --check`：今回の変更対象に空白エラーなし。
- 本番ビルドをローカル検証データで起動し、11ページのHTTP 200と見出し、DM詳細のHTTP 200を確認。
- 未ログイン時のログイン転送／API 401、未知の作成ツールの404、不正IDの400、下書き作成の201、1080×1350px PNGの登録の201、ID指定での素材取得、登録後も下書きのままであること、別Originの403を確認。

本番ビルドは、HEADの追跡済みファイルに今回の変更を重ねた専用コピーで実行した。ユーザーの未コミット原稿と無関係な変更は含めていない。実装・仕様のコピーが元ファイルと一致することも確認した。

## 視覚・外部確認の制限

ローカル専用のSupabase相当の認証・データを用意し、通常の管理者認証を通る検証用Next.jsサーバーを起動した。HTTP経由のページ・API確認は成功したが、ブラウザツール自体の接続／インベントリ取得がタイムアウトしたため、PC・スマートフォンのキャプチャ、実ブラウザでの入力保持、作成画面でのPNG生成からDM登録までの一連操作は未確認。

実装コードのレスポンシブ指定と操作ラベルは確認したが、視覚確認の成功とは扱わない。ブラウザの視覚証跡は作成していない。登録テストの書込みと画像はローカルのメモリ上のデータに限定し、本番データへの書込み、外部への画像アップロード、自動DM送信、デプロイは行っていない。

## 再確認方法

`node scripts/instagram-admin-qa-server.mjs` でローカル検証用サーバーを起動できる。画面は `http://localhost:3100`。認証は検証専用の `instagram-qa@example.test` / `fixture-only` を使用する。本番の認証・データに接続しない。

ビルド済みの作業コピーでは `node scripts/instagram-admin-qa-server.mjs --start` で起動し、別のターミナルから `node scripts/instagram-admin-qa-smoke.mjs` を実行すると、認証済みページと登録APIを再確認できる。終了時にサーバーを停止すると検証用データは破棄される。
